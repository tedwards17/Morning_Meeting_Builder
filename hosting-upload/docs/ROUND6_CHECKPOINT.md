## Cause and trace

- Content's submit handler performs native required-field/URL validation, then the recovered schema validation, description/media/link checks and duplicate confirmation. Its shared runner previously sent thrown validation/API errors to a global banner outside the top-layer modal. The modal obscured the error, leaving the form looking unresponsive. The fixed sidebar also covered the left part of that banner outside modals.
- Library create/rename used a prompt that closed before asynchronous persistence. A failed save lost the name input and reported the error elsewhere. No library-success confirmation was supplied.
- Location accounts could open creation/editing controls, but PHP records/batch already required Administrator or Content Manager for shared libraries/content. Changing location-sharing permissions was not warranted. Report viewers remain excluded from content navigation, and PHP denies their writes too.
- The API returned opaque request IDs and safe unexpected-failure messages, but runtime.api discarded the IDs. Failed authentication also unmounted the open draft.
- The actual path is form → serialized AppProvider update → full-state schema parse → repository.save diff → records/batch with expected_version → PHP role/target/library/media validation → transaction writing records, record_versions, sync_changes and audit_log → returned authoritative IDs/versions → IndexedDB → React list. Successful persistence occurs before success feedback. Existing PHP version conflicts prevent stale writes.
- **Authorized v0.5.4 library and text creation passed in a clean local real-PHP/MariaDB browser reproduction.** A universal authorized-account save defect or the exact historical live-site failure was not reproduced. Confirmed failure modes are obscured validation/denial/server feedback, lost library prompt input, and misleading role controls. The live PHP logs/database/private configs were not accessed. This patch makes the next host-specific failure diagnosable rather than asserting an unobserved hosting cause.

## Completed changes and decisions

- Content save/upload/archive failures are caught inside its open modal, displayed with an accessible alert, brought into view, and retain input. Native invalid fields and recovered-schema errors identify the field. Buttons show saving state; duplicate clicks and closing during a pending operation are prevented.

Archive errors use the same inline alert. Success updates/selects the library tab; content success updates the list, selects its library and clears incompatible filters so the saved item remains findable.
- Current roles are unchanged: Administrator/Content Manager may create/edit; Location is read-only for shared content with upfront role guidance and disabled creation/upload/save controls. Server denials give the same actionable role explanation. Report viewer writes remain denied.
- API errors preserve validated opaque request IDs. Unexpected 5xx responses are sanitized in the client as well as PHP. Native/schema/API validation, access denied, stale-write conflict, network failure and unexpected server failure remain distinguishable. Expired sessions keep an active content/library draft mounted (including during background sync); closing the draft returns to sign-in.
- Global warning occupies the desktop content column (238px/205px sidebar widths), and sits above the mobile drawer. Form errors live in the modal's top layer. English/Spanish UI messages added without translating library content.
- Existing required-field rules retained: title and description; media for Image/Image + text/local video; valid required link for link/video types. Library names are still required. One demonstrated validation bug corrected: PHP's 300-byte library name limit rejected valid multibyte names that the frontend allowed. It now counts UTF-8 characters, as the title validator already did. Whitespace-only library names are rejected consistently with the original prompt's trim behavior. 300/301-character checks cover this boundary.
- No SQL migration, dependency change, provider change, captions/presentation navigation change, location-sharing feature, visual template redesign, media lifecycle/config change, or production Node service. Prebuilt hosting-update/public_html excludes the live server-paths.php/config.js/root .htaccess. No real private/media path is packaged or replaced. Root Pages preview files are left unchanged.
